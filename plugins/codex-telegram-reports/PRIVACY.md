# Данные и доступ

Codex Telegram Reports работает локально на компьютере пользователя. У проекта
нет собственного облачного сервера, аналитики или центральной базы аккаунтов.

## Собственные Telegram API-реквизиты обязательны

Каждый пользователь регистрирует своё приложение на https://my.telegram.org и
вводит собственные `api_id` / `api_hash` в локальный мастер. В исходниках, архиве,
GitHub Actions и настройках по умолчанию ключей разработчика нет. Мастер не
запрашивает их у стороннего сервера. QR-вход также требует эти реквизиты.

Для отправки используется отдельный Telegram USER-аккаунт, авторизованный самим
пользователем. Телефон, код и пароль 2FA вводятся локально; код и пароль не
сохраняются приложением. Telegram-сессия даёт доступ к аккаунту, а не только к
группе отчётов. Используйте отдельный аккаунт без личной переписки.

## Куда поступают сведения

- Telegram получает имя проекта, начало/прогресс/блокировки и последний публичный
  ответ Codex в кратком виде; полный текст доступен по `/full`. Начало нейтральное:
  исходный запрос пользователя не копируется.
- По прямой просьбе владельца Telegram получает выбранные файлы рабочей копии,
  включая готовые сборки, игнорируемые Git. Текст проходит эвристическое скрытие
  секретов; бинарные документы/архивы не изменяются и не сканируются изнутри.
- Вопросы из Telegram обрабатываются через установленный Codex CLI с его текущей
  авторизацией и провайдером. Используются отчёты, краткие заметки задачи,
  предыдущие уточнения и ограниченный снимок текстовых файлов рабочей копии.
- Файлы, прочитанные инструментами для ответа, поступают модели Codex. Цитаты
  кода и объяснения могут попасть в ответ Telegram. Применяются условия и лимиты
  используемых пользователем сервисов Telegram и Codex.
- Сырые разговоры Codex, скрытые рассуждения и произвольные домашние файлы не
  импортируются. Известные секретные пути/файлы исключаются. Git-ignored файлы
  исключены из снимка для анализа, но доступны для явного запроса вложения.
  Эвристическое скрытие ключей не гарантирует распознавание любого секрета.

Группа закрытая, с одним разрешённым владельцем. Telegram-группы не являются
Secret Chats. Любой добавленный в группу участник сможет видеть её темы; плагин
не предоставляет разграничения доступа между темами. Он отвечает только
владельцу и не принимает новые задачи, изменения файлов и разрешения на действия.

## Управление и хранение

Новые установки по умолчанию подключают только выбранные проекты. Режим всех
проектов включается пользователем явно. `project disable` приостанавливает очередь
и вопросы конкретного проекта; уже отправленные сообщения сохраняются в Telegram.

Локальные настройки, сессия, отчёты и вопросы хранятся в
`~/.codex-telegram-reports`: каталог 0700, приватные файлы 0600. База не имеет
дополнительного шифрования на уровне приложения; доступ защищён правами ОС.
Снимки и scratch для вопросов временные. История отчётов не удаляется автоматически.
Копии запрошенных вложений сохраняются в `attachments/` с правами 0600, включая
после отправки. Имена доступных файлов могут поступать модели при запросе вложения;
содержимое бинарных файлов через модель не передаётся.
Резервные копии компьютера могут содержать эти данные.

`service uninstall` отключает автозапуск; `logout` отзывает сессию в Telegram.
После остановки службы и выхода локальные данные можно удалить вручную.
Удаление локальных данных не удаляет группу или сообщения из Telegram.
Сессии также отзываются через Telegram → Настройки → Устройства.

Не публикуйте config.json, файлы session, БД, QR-коды и приглашения в GitHub Issues.
`doctor --json` предназначен для диагностики без содержимого сообщений и ключей;
перед публикацией всё равно просмотрите вывод.

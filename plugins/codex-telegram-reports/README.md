# Codex Telegram Reports

Отчёты от **отдельного пользователя Telegram** в закрытой группе: по теме на проект
или выбранную рабочую копию. Подключаются выбранные пользователем проекты; доступен режим «все автоматически».
В теме можно обсуждать статус, код, изменения и варианты следующих шагов. Новые задачи,
разрешения, отмена и команды разработки через Telegram не принимаются.

## Установка из GitHub (macOS beta)

Нужны macOS, Python 3.11+, Git и авторизованный Codex CLI 0.155.1 или новее.
Проверенная версия Codex — 0.155.1; будущие версии могут потребовать обновления плагина.

**Каждый пользователь получает собственные `api_id` и `api_hash`**:
[my.telegram.org → API development tools](https://my.telegram.org).
В поставке нет общих API-реквизитов и ключей разработчиков. QR-вход не заменяет
регистрацию собственного API-приложения. Если Telegram не даёт создать приложение,
настройку нужно отложить — чужие ключи плагин не подставляет.

Из корня клона репозитория:

```sh
python3 plugins/codex-telegram-reports/scripts/setup.py --qr
```

Мастер проверяет Codex, устанавливает отдельную среду Python, запрашивает ваши
API-реквизиты, выбор проектов и вход специального Telegram-аккаунта. Затем просит
@username личного аккаунта, создаёт закрытую группу, запускает службу, подключает
каталог плагинов из этого клона и предлагает отправить тестовый отчёт.
Telega и BotFather не нужны. Коды, пароль 2FA и api_hash вводятся только локально.

По умолчанию новой установки включаются только явно выбранные проекты. Для всех
проектов можно выбрать второй вариант в мастере. При обновлении прежний выбор
сохраняется. Подробности: [PRIVACY.md](PRIVACY.md).

В Telegram на телефоне выберите специальный аккаунт: **Настройки → Устройства →
Подключить устройство**, затем отсканируйте QR из локальной страницы браузера.
Страница имеет права 0600; изображение токена удаляется после завершения/отмены.
Номер и код доступны при запуске без `--qr`; пустой ввод не отправляется,
`/resend` учитывает ограничения Telegram, `/qr` переключает на QR.

Откройте выданную ссылку **личным** аккаунтом. Ссылка действует сутки и требует
заявку; служба одобрит только указанный ID. Все участники группы видят все темы.
Повторный `setup-group --owner @username` выдаёт ссылку для прежней группы;
сначала остановите службу. Смена владельца/служебного аккаунта в существующей
истории не поддерживается. Для первого входа нужен доступный личный @username.

Откройте **новый разговор Codex**, проверьте `/hooks` и доверьте четыре обработчика:
SessionStart, UserPromptSubmit, Stop, Interrupt. Мастер не подтверждает доверие
вместо пользователя. Без доверенных hooks автоматическое начало/итог не работают;
MCP остаётся доступным. В Desktop также требуется поддержка plugin hooks.

Каталог репозитория называется `local-dev` (имя сохранено для совместимости).
Мастер использует штатные команды Codex:

```sh
codex plugin marketplace add /absolute/path/to/CodexTelegram
codex plugin add codex-telegram-reports@local-dev
```

Это локальный клон GitHub-каталога: сохраняйте его для обновлений. Установка одного
плагина из каталога не заменяет установку Python runtime и Telegram onboarding.

MCP и hooks запускают установленный runtime напрямую через изолированный Python (`-I`),
без зависимости от текущей папки или раскрытия `${PLUGIN_ROOT}`. В legacy
`.mcp.json` Codex 0.155.1 не раскрывает эту переменную в аргументах stdio.
В hooks путь к версии кэша также не используется: старую папку Codex может удалить
во время обновления. Мастер сохраняет минимальные launcher-файлы для разговоров,
которые ещё используют прежние команды hooks. При ошибке MCP после обновления откройте
новый разговор, чтобы Codex загрузил актуальную конфигурацию плагина.

## Что отправляется

- UserPromptSubmit: нейтральное начало, без копирования исходного запроса.
- `telegram_report`: краткий содержательный прогресс, блокировка, проверенный итог.
- `telegram_task_context`: краткая цель, план, решения, результаты проверок и
  следующие шаги для уточнений; сохраняется локально, без отдельного сообщения.
- Stop: краткое представление последнего публичного ответа ассистента. Это конец ответа, не доказательство
  завершения всей задачи; формулировка самого ответа определяет реальный статус.
- Interrupt: сообщение о прерывании ответа.

Сырые команды, tool outputs, скрытые рассуждения и история других чатов не читаются.
Есть базовое скрытие типовых ключей/паролей, но оно не заменяет аккуратного выбора
текста отчёта. Все участники Telegram-группы видят все темы; эта версия рассчитана
на одного владельца и отдельный служебный аккаунт.

Git worktrees и подкаталоги обычного репозитория используют одну тему. Разные
репозитории с одинаковым именем остаются разными проектами. Для каталога без Git
идентичностью служит абсолютный путь. Перемещение проекта пока создаёт новую тему.
Для постоянных ролей можно явно выделить тему рабочей копии:

```sh
python3 plugins/codex-telegram-reports/scripts/run.py project topic /path/Telega-work/clients --name 'Telega · clients'
python3 plugins/codex-telegram-reports/scripts/run.py project topic /path/Telega-work/server --name 'Telega · server'
python3 plugins/codex-telegram-reports/scripts/run.py project topic /path/Telega-work/integration --name 'Telega · integration'
```

Маршрут хранится локально, действует для hooks и MCP, включая запуск из подкаталога.
Он наследует выбор подключения репозитория; отключённый проект не включается.
Служба создаёт/переименовывает темы автоматически. Старые сообщения остаются в
прежней теме, ответы на них сохраняют исходную задачу и рабочую копию. Скрипты
`telega codex clients|server|integration` менять не требуется: они уже выбирают cwd.
После обновления откройте новые разговоры Codex, чтобы перезапустить их MCP.

Длинные отчёты дополнительно сокращаются локально без перефразирования фактов:
приоритет имеют результат, проверки, ошибки, ограничения и следующие шаги.
Повторы и подробности опускаются; ориентир 1400 символов — мягкий лимит, важные
предупреждения могут сделать сообщение длиннее. Исходный публичный текст сохраняется
в базе (до 24 000 символов). Ответьте `/full` на отчёт или ответ службы, чтобы получить
его полностью. `/status` показывает до трёх последних задач кратко. Встроенные
инструкции Codex также просят краткие ответы без потери существенных оговорок.

### Файлы по запросу

В Telegram: `/file build/app.apk`, `/file "docs/мой файл.pdf"` или «пришли APK».
Ответьте на отчёт нужной задачи, чтобы выбрать её рабочую копию. Обычная просьба
использует отдельный Codex для поиска пути; при нескольких версиях он должен уточнить
выбор. Точный `/file` работает без модели. Файл отправляется документом в ту же тему
ответом на запрос. Генерация и сборка новых файлов из Telegram не запускаются.
В основном Codex можно попросить «отправь этот файл в Telegram» — для этого есть
`telegram_send_file`. Автоматической отправки всех артефактов нет.

До трёх файлов за запрос, 2000 MiB на поддерживаемый документ/сборку, 8 MiB на UTF-8
текст. Поддерживаются APK/AAB/IPA, DMG/PKG, ZIP/TAR/GZ/7Z, PDF, Office, изображения,
аудио/видео и текст. Разрешены готовые файлы в build/dist/.workspace/artifacts,
даже если они игнорируются Git. Ссылки, выход за рабочую копию, ключи, session,
базы и известные секретные пути исключены. Типовые секреты в тексте скрываются;
бинарные документы и архивы отправляются без изменения содержимого.

Для доставки сохраняется приватная копия в `attachments/` рядом с базой. Изменение
оригинала не меняет вложение в очереди; повтор использует прежний Telegram random_id.
Копии сохраняются после доставки вместе с историей, автоматической очистки пока нет.

## Уточнения

`/status` показывает последние доставленные отчёты без вызова модели. `/help`
объясняет доступные действия. Обычные вопросы обрабатывает отдельный ephemeral
`codex exec` с текущей авторизацией Codex; отдельный OpenAI API key не требуется.

После сохранения вопроса служба отмечает его прочитанным в соответствующей теме
и ставит реакцию 👀: вопрос принят, ответ готовится или ожидает доставки.
После подтверждённой доставки всех частей ответа реакция снимается. Подтверждения
обрабатываются отдельно от модели: новый вопрос получит отметку, даже если
предыдущий ответ ещё готовится. Обычно это занимает несколько секунд после
поступления сообщения, пока Mac работает и Telegram доступен.

Состояние подтверждений сохраняется в SQLite. После перезапуска или сетевого
сбоя операции повторяются с backoff; реакция заменяется, а не дублируется.
Если реакции отключены в группе, отметка прочтения остаётся, ответы продолжаются.
Прочтение обновляется только после сохранения принятого вопроса; неизвестные
пользователи и темы не получают подтверждений. Старые завершённые разговоры
автоматически не помечаются реакциями.

Контекст состоит из доставленных отчётов, заметок задачи и предыдущих уточнений
по этой задаче. Ответьте на отчёт или на ответ службы, чтобы сохранить выбор задачи
и её рабочей копии. Без reply выбирается последний доставленный отчёт на момент
получения вопроса. Снимок всегда новый, поэтому отражает код на момент вопроса,
а не обязательно на момент старого отчёта. Для старых отчётов без рабочего пути
явно указывается использование корня проекта. Если сохранённая рабочая копия
удалена или больше не принадлежит проекту, остаются только отчёты.

На каждый вопрос создаётся ограниченный снимок текстовых файлов нужной рабочей
копии, включая незакоммиченные изменения. Из Git берутся branch, HEAD, последние
коммиты и diff относительно HEAD. Снимок не является атомарной копией изменяемого
дерева: меняющиеся при чтении файлы пропускаются. Игнорируемые Git файлы, известные
пути секретов, ключи, БД, бинарные файлы, ссылки и зависимости исключаются;
типовые секреты в содержимом скрываются эвристически. Это не гарантия распознавания
произвольного секрета, помещённого в обычный исходник. Лимиты: 4000 файлов,
512 KiB на файл, 24 MiB суммарно. Пропуски и усечение diff указаны модели.
Она ссылается на файлы/строки и различает отчёты, код и собственные предположения.

Приватный MCP `project_reader` доступен только обработчику вопросов: обзор,
список файлов, чтение, поиск, diff и диагностические Python-скрипты. Модель работает
вне проекта с `--ignore-user-config`, отключёнными плагинами, приложениями,
shell/exec, браузером и агентами. Встроенный code-mode host нужен для транспорта
вызовов MCP; он не включает общий shell. Дополнительно используются read-only
sandbox, approval=never и PreToolUse hook, пропускающий только шесть инструментов
этого MCP. Перед запуском App Server проверяет определение guard;
только его актуальный hash получает доверие в параметрах отдельного запуска.
Другие hooks, кроме управляемых администратором, отключаются для уточнений;
глобальная конфигурация не меняется.
Обход проверки доверия hooks не используется. Управляемые администратором политики
Codex продолжают действовать.
При несовместимой конфигурации запуск завершается ошибкой. Ошибки модели не
останавливают доставку отчётов. Плагин не читает базу разговоров Codex и не вызывает
resume/steer для рабочих разговоров; контекст решений передаётся основным Codex
явно, через `telegram_task_context`, без скрытых рассуждений и сырых запросов.

### Диагностические скрипты

`run_python` проверен на macOS с Codex 0.155.1. Скрипт получает `PROJECT` (путь к
очищенному снимку) и `SCRATCH` (временная папка). Разрешена стандартная библиотека
Python: например, AST, подсчёты, анализ структуры исходников и конфигурации.
Файлы проекта и снимка нельзя менять. Доступа к домашним файлам, переменным
окружения с ключами, сети и сервисам нет. Создание дочерних процессов запрещено.
Реальные сведения об окружении ограничены платформой и версией Python обработчика;
установленные зависимости и запущенное приложение эта диагностика не проверяет.

Каждый скрипт запускается через `codex sandbox` с отдельным профилем: доступ на
чтение к снимку и среде Python, запись только в SCRATCH, сеть выключена. Профиль
учитывает managed config. Ограничения: 6 секунд CPU, 15 секунд ожидания, 24 KB
вывода, 1 MiB на записываемый файл и четыре запуска на вопрос. Родительский процесс
проверяет RSS с порогом 518 MiB; это периодическая проверка, не жёсткая квота памяти.
На других ОС доступны чтение/поиск, а скрипты отказывают до отдельной проверки
изоляции. При ошибке песочницы выполнение без неё не запускается.

Примеры вопросов: «Где реализованы повторные попытки?», «Что изменилось относительно
HEAD?», «Посчитай через AST обработчики и покажи, какие события они обслуживают»,
«Какие варианты решения блокировки есть?». Запуск разработки, изменения,
развёртывание и разрешения по-прежнему задаются в основном Codex.

## Служба и данные

```sh
python3 scripts/run.py doctor
python3 scripts/run.py projects
python3 scripts/run.py service status
python3 scripts/run.py service stop
# foreground, в том числе Linux:
python3 scripts/run.py run
```

Данные: `~/.codex-telegram-reports` (каталог 0700, файлы 0600):
`config.json`, `telegram-user.session`, `reports.sqlite3`, `venv/`, `service.log`.
Другой каталог задаётся `CODEX_TELEGRAM_REPORTS_HOME` одинаково для MCP, hooks и
службы. Сессия Telegram даёт доступ к аккаунту: не добавляйте её в Git.
Служба запускается одним процессом; lock предотвращает конкурирующие writers.
Логи не содержат отчётов, входящих вопросов, номера, кодов и секретов.

SQLite сохраняет части сообщений и Telegram random_id перед отправкой; повторы
используют прежние IDs. Это защита от типовых повторов и потерянных ACK, не обещание
вечной exactly-once доставки со стороны внешнего сервиса. Ошибки остаются в очереди
с backoff и видны в doctor. Удалённую/закрытую тему нужно восстановить в Telegram;
служба не создаёт замену молча. История вопросов догоняется по сохранённому курсору.
На первом создании группы курсор ставится на её текущую историю.

Mac должен работать и иметь сеть. Во время сна/выключения отчёты и ответы задерживаются.
LaunchAgent запускается после входа в macOS, не на удалённом сервере.

## Проекты, обновление и удаление

Команды из корня репозитория:

```sh
python3 plugins/codex-telegram-reports/scripts/run.py project enable /absolute/path/to/project
python3 plugins/codex-telegram-reports/scripts/run.py project disable /absolute/path/to/project
python3 plugins/codex-telegram-reports/scripts/run.py reporting all
python3 plugins/codex-telegram-reports/scripts/run.py reporting selected
python3 plugins/codex-telegram-reports/scripts/run.py doctor --mcp
python3 plugins/codex-telegram-reports/scripts/run.py test-report
```

Явное enable/disable имеет приоритет над общим режимом. Отключение приостанавливает
очередь проекта и новые вопросы, не удаляет отправленное из Telegram. Уже начатый
сетевой запрос может завершиться. При повторном включении сохранённая очередь
продолжает доставляться; новые отчёты во время отключения не записываются.
`doctor --json --mcp` возвращает диагностический JSON без содержимого отчётов и
API-реквизитов; код выхода 1 означает незавершённую настройку или неисправность.

Обновление после просмотра изменений:

```sh
git pull --ff-only
python3 plugins/codex-telegram-reports/scripts/setup.py --update
```

Новая среда сначала полностью устанавливается и проверяется; рабочая служба
останавливается только на переключение. При ошибке установки активная среда
сохраняется. Runtime, плагин и служба обновляются одним мастером. После этого
нужны новый разговор и проверка доверия изменённых hooks в Codex.
Сессия Telegram, настройки и история сохраняются. Зависимости runtime закреплены
в `requirements.lock`; установке нужен интернет для загрузки Python-пакетов.

Для аварийного отката **только Python runtime**:

```sh
python3 plugins/codex-telegram-reports/scripts/install.py --rollback
```

Предыдущая среда сохраняется в `runtimes/`. Это не откат базы и кэша Codex.
Для полного возврата используйте предыдущий проверенный Git ref и его мастер
`setup.py --update`; не откатывайте несовместимые миграции базы без резервной копии.

Отключение автозапуска и отзыв Telegram-сессии:

```sh
python3 plugins/codex-telegram-reports/scripts/run.py service uninstall
python3 plugins/codex-telegram-reports/scripts/run.py logout
codex plugin remove codex-telegram-reports@local-dev
```

Если Telegram недоступен, отзовите сессию через **Настройки → Устройства** в его
официальном клиенте. После выхода локальный каталог `~/.codex-telegram-reports`
можно удалить вручную, если история больше не нужна. Удаление каталога не удаляет
сообщения и группу в Telegram. Не удаляйте данные, пока служба работает.

## Проверка разработки

Из корня репозитория:

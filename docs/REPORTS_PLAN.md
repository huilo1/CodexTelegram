# Telegram-отчёты Codex — план и решения

Дата: 20 сентября 2026.

## Требования

- Отдельный пользователь Telegram, вход по номеру и коду, отдельная MTProto-сессия.
- Закрытая супергруппа с темами, вступление по ссылке. Одна тема на проект,
  несколько задач/разговоров Codex внутри темы.
- Все проекты подключаются автоматически в сеансах с включённым плагином.
- Начало, существенный прогресс, блокировки и итог; без потока команд и сырых логов.
- Вопросы о статусе и отчётах разрешены; постановка задач и управление разработкой отсутствуют.
- Участники группы видят все темы. Для разных аудиторий нужны разные группы.

## Исследование

Старый runtime в этом репозитории — Bot API + `codex exec resume`, личный чат,
удалённая разработка. Он сохранён как legacy и новым плагином не запускается.
Первоначальная локальная установка использовала только API ID/hash соседнего
проекта, не его сессию. Для GitHub-версии это не применяется: каждый пользователь
получает собственные API ID/hash и вводит их локально; общие ключи не распространяются.

Сравнены публичные проекты:

- https://github.com/patriceac/codex-telegram — MCP notify/ask, forum topics,
  App Server; преимущественно topic = thread и удалённые задачи.
- https://github.com/vruru/telegram_codex_bridge — Go, App Server, SQLite,
  topic = thread, входящие сообщения запускают разработку.
- https://github.com/Headcrab/telecodex — Rust, topic-aware remote CLI.

Новый плагин не копирует их исходники. Python/Telethon соответствует существующему
стеку и требованию отправлять от имени отдельного пользователя.

Официальные источники:

- https://learn.chatgpt.com/docs/developer-commands — `/side`: временный отдельный разговор.
- https://learn.chatgpt.com/docs/app-server — `thread/read`, `thread/fork`.
- https://learn.chatgpt.com/docs/hooks — lifecycle hooks, trust, поля событий.
- https://core.telegram.org/api/forum — группы, темы, reply_to_top_id.
- https://docs.telethon.dev/en/stable/basic/signing-in.html — пользовательская авторизация.

## Реализация

1. Самостоятельный `plugins/codex-telegram-reports`: manifest, MCP, skill, hooks,
   Python runtime, инструкции установки. Старый plugin не менять на новую семантику.
2. SQLite: проекты, задачи, отчёты, очередь исходящих частей сообщений, вопросы,
   курсор истории группы. Стабильные Telegram random_id для повторов доставки.
3. Hooks автоматически регистрируют проекты и отмечают начало/итог. MCP передаёт
   содержательные промежуточные отчёты. Инструкция hook напоминает агенту об этом.
4. Telethon service создаёт/переиспользует темы, доставляет очередь, получает
   вопросы только от разрешённых пользователей в привязанной теме.
5. Уточнения: отдельный ephemeral Codex запуск по опубликованным отчётам, заметкам
   задачи, истории уточнений и очищенному снимку её рабочей копии. Приватный MCP
   разрешает чтение, поиск, Git diff и Python-диагностику в отдельной песочнице.
   Общие shell/exec и интеграции отключены; guard допускает только этот MCP.
   Основной thread не resume/steer/fork: это исключает наследование активной цели,
   инструментов и непредназначенного для группы контекста. Это аналог поведения
   `/side`, не попытка автоматизировать UI-команду.
   Python получает стандартную библиотеку, снимок на чтение и временную папку
   на запись; без сети, секретов, запуска дочерних программ и изменений проекта.
   Контекст решений передаётся через `telegram_task_context`, без чтения сырых
   разговоров Codex. Ответы ссылаются на файлы/строки и время снимка.
6. CLI: собственные API ID/hash через локальный мастер, QR/код, создание группы,
   выбор проектов, doctor, обновление/откат runtime, выход и launchd.
7. Проверки: маршрутизация нескольких задач/проектов, deny-by-default ACL,
   дубликаты, повторная доставка, отказ Telegram/Codex, ограничение вопросов,
   упаковка и реальный MCP handshake. Живой Telegram smoke — после входа.

## Границы

Плагин работает там, где он включён и hooks доверены. Сеансы, уже открытые до
установки, нужно открыть заново. Это не глобальное наблюдение за чужими чатами.
Служба получает сообщения, пока Mac работает; после сна догоняет историю.
Не заявлять завершённую Telegram-проверку до реальной авторизации и доставки.

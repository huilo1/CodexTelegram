# Выпуск Codex Telegram Reports через GitHub

Первая распространяемая версия — macOS beta 0.2.0. Каталог репозитория имеет
имя `local-dev`; плагин — `codex-telegram-reports`. Legacy-плагин остаётся отдельным.
Лицензия MIT в каталоге нового плагина относится к нему, а не меняет лицензию
прежних частей репозитория.

## API-реквизиты

Выпуск всегда использует BYO credentials: каждый пользователь получает собственные
api_id/api_hash. Никаких общих значений, файлов из Telega, session или готового
config.json в поставке. CI не требует Telegram/OpenAI secrets и не входит в аккаунты.

## Проверки перед выпуском

Из корня репозитория:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r plugins/codex-telegram-reports/requirements.lock
.venv/bin/python -m pip install -e '.[dev]' -e plugins/codex-telegram-reports
.venv/bin/pytest -q
python3 scripts/check_release_secrets.py --history
python3 scripts/build_reports_release.py
```

На компьютере разработчика дополнительно сравните исходники/историю с реальными
локальными API-реквизитами, не выводя их:

```sh
python3 scripts/check_release_secrets.py --history --local-config "$HOME/.codex-telegram-reports/config.json"
```

Проверка эвристическая; просмотрите diff и состав ZIP. Не публикуйте локальные
config/session/БД/логи, QR-страницы или приглашения. `dist/` игнорируется Git.
Архив содержит только новый плагин, его каталог и публичные инструкции;
внутренняя память разработки, история Git и runtime в него не входят.

Сверьте базовую версию в pyproject.toml и manifest; для изменений локального кэша
используйте cachebuster/reinstall из plugin-creator. Обновляйте CHANGELOG.md.
requirements.lock фиксирует версии runtime; это не универсальный lock с хешами
для всех ОС/Python. Изменения пинов требуют повторной установки и тестов.

## Проверка на отдельной установке

Автотесты не заменяют эти шаги. На другом Mac или в отдельном профиле macOS:

1. Установить Python/Codex и войти в свой Codex.
2. Клонировать выпуск или распаковать ZIP и запустить `setup.py --qr`.
3. Ввести собственные API-реквизиты и войти своим отдельным Telegram-аккаунтом.
4. Выбрать проекты, войти в закрытую группу личным аккаунтом, получить тестовый отчёт.
5. Доверить четыре hooks; проверить начало, прогресс и итог новой задачи.
6. Задать вопрос к отчёту: получить 👀 и ответ; проверить `/status`.
7. Проверить отключение проекта, обновление, перезапуск Mac и удаление/выход.

Запишите фактические macOS/архитектуру/Python/Codex. Не заявляйте поддержку
Intel/Apple Silicon или новых версий Codex только по наличию CI-конфигурации.
CI пропускает реальную песочницу, если Codex отсутствует; живой sandbox проверяется
отдельным тестом на Mac с Codex. Настоящая авторизация в CI не выполняется.

## Публикация

После проверки подготовьте commit с исходниками, каталогом, тестами и документацией,
затем tag/release. Прикрепите ZIP и соответствующий `.sha256`; опишите проверенную
среду и известные ограничения. Архив не включает зависимости — установка обращается
к Python package index. Проверьте README со свежего клона опубликованного Git ref.

GitHub Actions выполняет тесты и собирает артефакт; он не создаёт публичный release
автоматически. Включите private vulnerability reporting в настройках GitHub, если
этот канал планируется использовать для сообщений о безопасности.

Основной путь установки — Git clone + setup.py: каталог и runtime используют
один checkout. Codex также поддерживает прямой GitHub-каталог:
`codex plugin marketplace add huilo1/CodexTelegram`. Этот вариант сам по себе не
устанавливает runtime/Telegram-сессию; не подключайте одновременно две разные
копии одного каталога. [Официальная упаковка и каталоги](https://developers.openai.com/plugins/build/plugins).
